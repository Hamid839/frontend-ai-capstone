**Student:** Hamid Shoukat  
**Track:** General AI Fluency  
**Week:** 4 — Build

## 1. My requirements and constraints

Before selecting my stack, I considered four requirements.

**Budget:** I want to use free tools and hosting services. I do not want my portfolio to depend on paid subscriptions or services.

**My current skill level:** I have experience with HTML, CSS, JavaScript, React, TypeScript, Next.js, Tailwind CSS, Git and GitHub through my learning journey and internship projects. However, I am still improving my ability to independently design application architecture, troubleshoot complex issues and maintain larger applications. I use AI coding assistants, but I want to understand and review the code they generate.

**What my portfolio needs to do:** My target audience is technical hiring managers and frontend engineering recruiters. My main goal is to demonstrate that I can build responsive frontend interfaces that connect to real data and solve practical problems.

My planned pages are:

- Home: Introduce myself, communicate my main claim and highlight my strongest work.
- Work: Showcase MedNoviAI, FocusBoard and other verified projects.
- Case studies: Explain project context, my contribution, technical implementation, screenshots, challenges and lessons.
- About: Present my background, education, skills and development approach.
- Contact: Provide verified email, GitHub and LinkedIn links.

The main visitor journey is Home → Work → Case study → Contact.

**How my work must be displayed:** My portfolio needs project screenshots and image galleries, live demonstrations where available, GitHub repositories, and readable technical case studies. It must show what I personally contributed rather than simply listing project names.

**Dynamic requirements:** I do not need a backend for the initial portfolio. Project information, screenshots, case studies and contact links can be displayed using static content. A contact form or AI chatbot can be considered later.

## 2. Three stack options considered

### Option 1 — No-code website builder

I considered Carrd or Framer.

This would allow me to create a portfolio using drag-and-drop components, add project screenshots, and link to my GitHub repositories and demos.

Hosting would use the builder's free publishing option.

Backend requirement: No.

The main advantage is speed and simplicity. The disadvantage is that it offers less control over implementation and does not demonstrate my frontend coding ability as effectively.

### Option 2 — Plain HTML, CSS and JavaScript

I considered building the portfolio with HTML, CSS and JavaScript, using Netlify or Cloudflare Pages for free hosting.

Backend requirement: No.

This option is simple, lightweight and suitable for a static developer portfolio. It would also help me strengthen my understanding of the fundamentals.

However, I already have an existing Next.js project. Rebuilding it using plain HTML, CSS and JavaScript would mean repeating work and manually recreating some of the reusable structure and routing.

### Option 3 — Next.js, React and TypeScript

I considered continuing with Next.js App Router, React, TypeScript and Tailwind CSS, using GitHub for version control and Vercel for hosting.

Backend requirement: Not initially.

This option supports reusable components, structured routing, responsive layouts, image galleries, detailed case studies, code links and interactive demonstrations. It also gives me the flexibility to add server-side functionality later if a genuine requirement appears.

The disadvantage is that I must maintain dependencies, understand the framework, troubleshoot build issues and avoid becoming overly dependent on AI-generated code.

## 3. Pressure-testing my decision

I considered what I would lose by selecting the simplest option. A no-code builder would help me publish quickly, but it would not demonstrate my actual frontend development skills. Plain HTML and CSS would be easier to maintain, but moving my existing project to that stack would require unnecessary rebuilding.

I also considered the maintenance requirements of Next.js. I will need to keep dependencies updated, understand the routing and component structure, review AI-generated code and troubleshoot deployment issues. I believe this is manageable if I keep the project scope focused and build incrementally.

I can finish the initial portfolio within two weeks if I prioritize the main pages, real project evidence and responsive design rather than adding unnecessary advanced features.

Next.js also supports the way my work needs to be displayed: project screenshots, real demos, GitHub repositories and detailed technical case studies.

## 4. My final decision

I have decided to continue with **Next.js App Router, React, TypeScript and Tailwind CSS, with GitHub and Vercel**.

I did not choose a no-code builder because I want the portfolio to demonstrate my frontend development ability, not only my design and content presentation skills.

I did not choose plain HTML, CSS and JavaScript because I already have a working Next.js foundation and would rather improve and maintain it than rebuild the same portfolio from scratch.

I chose Next.js because it supports my current project requirements and gives me room to expand later. I already have experience working with this stack, so I believe I can maintain it as long as I continue learning, understand the code and keep the architecture simple.

Most importantly, I do not need a backend yet. The first version of my portfolio can use static content, screenshots, project links and case studies. I will introduce dynamic functionality only when it solves a real problem.

**Final decision:** Continue with Next.js + React + TypeScript + Tailwind CSS + GitHub + Vercel. Keep the first release simple, focused and maintainable.
