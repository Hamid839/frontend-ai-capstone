# Identity Kit — Hamid Shoukat

**Purpose:** Establish one consistent visual identity for my portfolio so the interface supports my project evidence rather than competing with it.

## Typography

- **Font:** Inter, available free through Google Fonts.
- **Headings:** Inter SemiBold/Bold, weights 600–700.
- **Body:** Inter Regular, weight 400.
- **Buttons and labels:** Inter Medium, weight 500.

Use one font family throughout. Establish hierarchy with font size, weight, line height, and whitespace instead of adding decorative fonts.

## Color palette

| Role | Name | Hex |
|---|---|---|
| Primary | Forest green | `#1E6848` |
| Text | Near-black green | `#17231D` |
| Background | Soft near-white | `#F7F8F5` |
| Accent | Muted lime | `#B8D957` |

### Usage rules

- Use forest green for primary buttons, links, and key interactive elements.
- Use near-black green for headings and body text.
- Use soft near-white as the main page background.
- Reserve muted lime for small highlights.
- Check text contrast and accessibility before using accent colors for text.
- Do not introduce extra brand colors without a clear reason.

## Logo and favicon

Use a capital H monogram in near-white inside a rounded forest-green square. Keep the mark recognizable at 16×16 and 32×32 pixels.

The optional wordmark is “Hamid Shoukat” in Inter SemiBold, with “Frontend Developer” as a small secondary label.

## Two-line style note

Use Inter throughout, with forest green `#1E6848`, near-black text `#17231D`, a soft near-white background `#F7F8F5`, and muted lime `#B8D957` as the only accent.

Keep the mood calm, clear, and professional, with generous whitespace and consistent components so real project work—not decoration—gets the attention.

## Consistency rules

1. Reuse the same colors, typography, spacing, and button styles across all pages.
2. Keep layouts readable and responsive on mobile and desktop.
3. Use genuine project screenshots to demonstrate real work.
4. Avoid decorative gradients, competing colors, and unnecessary animations.
5. Do not invent project results, metrics, or personal details.
