## 3. Decide Once: Visual Identity Kit

### Design principle

The portfolio is the frame; my work is the painting. The design should make the work easier to understand, not compete with it.

### Typography

**Primary font:** Inter  

Use one font family for headings, body text, navigation, buttons, and labels. Create hierarchy through size, weight, line height, and spacing rather than introducing decorative fonts.

- Hero heading: bold, approximately 48–64px on desktop, scaled down on mobile.
- Section headings: bold, approximately 28–36px.
- Body text: 16–18px with comfortable line height.
- Navigation and labels: approximately 14–16px.
- Keep paragraphs readable and avoid overly long line lengths.

### Core color palette

| Role       | Color            | Hex     |
| ---------- | ---------------- | ------- |
| Primary    | Forest green     | #1E6848 |
| Main text  | Near-black green | #17231D |
| Background | Soft near-white  | #F7F8F5 |
| Accent     | Muted lime       | #B8D957 |

Use white surfaces and subtle neutral borders when necessary, without introducing additional competing brand colors.

**Usage rules:**

- Use near-black for most text.
- Use forest green for primary buttons, links, and important interactive elements.
- Use the near-white background as the default canvas.
- Use muted lime sparingly for small highlights or decorative details, not for long text.
- Check contrast before publishing. Do not assume that an accent color is readable on every background.

### Logo and favicon

Use a simple capital “H” monogram inside a rounded forest-green square. It should remain recognizable at a small browser-tab size.

Do not add complex illustrations, gradients, shadows, or decorative details that disappear when the icon is reduced.

### Layout and spacing

- Use a consistent content width.
- Align section headings, cards, and screenshots to a shared grid.
- Reuse a small set of spacing values.
- Give sections and project screenshots generous breathing room.
- Keep card borders and corner radii consistent.
- Use subtle transitions only when they improve feedback or navigation.
- Make mobile layouts as deliberate as desktop layouts.

### Two-line style note

> Use Inter throughout on a soft near-white background, with near-black text and forest green for important links and actions. Reserve muted lime for small accents, keep spacing generous, and let real project screenshots and demonstrated results provide the visual interest.

**Mood:** Calm, capable, clear, and practical.

## 4. Kill Your Darlings: Image Curation

### Image inventory

| Page or section | Image required                        | Source and decision                                                                  |
| --------------- | ------------------------------------- | ------------------------------------------------------------------------------------ |
| Home            | Portrait or personal photo, if useful | Use a genuine photo; do not generate an artificial portrait.                         |
| Home            | Featured project preview              | Use a real screenshot of an implemented feature.                                     |
| Work            | MedNoviAI project image               | Use a clean, cropped capture of my actual doctor search or appointment history work. |
| Work            | FocusBoard preview                    | Use a real screenshot of the running application.                                    |
| Case study      | Feature screenshots                   | Capture the actual interface and preserve readable text.                             |
| About           | Optional supporting visual            | Prefer whitespace or a subtle abstract visual; a decorative image is not mandatory.  |
| Shared layout   | Logo/favicon                          | Use the simple H monogram from the identity kit.                                     |

### Screenshot rules

- Capture the real application at a useful viewport size.
- Crop unnecessary browser chrome and unrelated content.
- Preserve enough context to explain the feature.
- Ensure text and controls remain legible.
- Do not replace real interface screenshots with AI-generated imitations.
- Do not show private data, secrets, or confidential team information.
- Do not claim that a mockup is a deployed feature.

### Generated-image decision

A restrained abstract visual may be used as optional supporting artwork in an introductory or transitional section. It must remain visually secondary and use the same forest-green, near-white, and muted-accent direction.

It must not be presented as evidence of a project I built.

### Rejected direction

A glossy, highly detailed, AI-generated hero with dramatic lighting, fake glass effects, and several competing colors. I rejected this direction because it would attract attention to the decoration rather than to the real frontend work the portfolio is meant to prove.

**Reason for rejection:** The portfolio should be remembered for the projects, implementation decisions, and evidence—not for a generated background.

**Final curation decision:** Prioritize genuine project captures. Use generated artwork only if it adds clarity without reducing the prominence or readability of the work. Leaving a section without an image is preferable to adding a decorative image that does not serve the proof.
